FSA-002 · Workflow Runtime

TaskFlow Runtime: plan the work, execute with bounded retries, verify the outcome, preserve the evidence

A dependency-light TypeScript runtime that turns workflow execution into an inspectable record. The implemented product is TaskFlow Runtime; TaskFlow Studio is the planned visual client and is not presented as shipped.

Stack
TypeScript · Node.js 22 · Web APIs
Tests
23 automated tests
Status
Pre-revenue · Runtime implemented
Role
Sole engineer

TaskFlow Runtime separates orchestration into explicit Plan → Execute → Verify phases. Typed workflow definitions declare steps, inputs, retry limits, and verification behavior. The engine owns sequencing, retries, event logging, cost aggregation, terminal status, metrics, and persistence; individual workflows own only their domain logic.

One product boundary, two names

TaskFlow Runtime is the code that exists today. It exposes typed workflow contracts, contract-tested HTTP behavior through a Node adapter, a Web Request/Response handler, a Vercel-compatible endpoint, atomic JSON run storage, and evidence-focused metrics. TaskFlow Studio is reserved for a future visual authoring and observability interface. The Studio is a product target—not a current capability.

The customer-oriented workflow

The included workflow processes consulting intake for a service business. It validates and normalizes submitted details, classifies the opportunity by budget, generates a consulting brief, and verifies that the brief preserves the requested service, goals, timeline, and qualification logic.

The checked demonstration intentionally injects one transient failure during qualification. The runtime records the failed attempt, retries within the step's declared limit, completes the brief, verifies the result, and persists the terminal run record.

The checked July 18, 2026 benchmark used eight synthetic cases repeated 25 times. It reported 100% expected-outcome match, 100% completion for valid cases, p50 latency of 0.040 ms, p95 latency of 0.136 ms, and $0 recorded adapter cost.

Scope warning: these are local deterministic results with synthetic data and no paid model, connector, hosted infrastructure, or production customer traffic. They do not establish production latency, general model quality, revenue, adoption, or operating workload.

Engineering and operations

  • Typed workflow definitions for steps, inputs, retry limits, and verification
  • Atomic file persistence with safe run identifiers
  • Structured retry exhaustion and verification failure behavior
  • Contract and HTTP behavior covered across Node and Web Request/Response boundaries
  • Node, Web API, Vercel, Docker, and bare-VPS deployment guidance
  • Architecture, threat model, dependency inventory, metrics methodology, security policy, and deployment documentation
  • Automated tests for workflow execution, retries, persistence, metrics, contract behavior, and failure paths

The runtime has no direct production package dependencies. Authentication, tenant isolation, managed durable storage, secrets, rate limiting, connector controls, observability, and compliance work remain production gates for any hosted Studio.

Commercial status

TaskFlow is pre-revenue. The previously discussed $39 / $99 / $249 tiers, visual canvas, managed connectors, SaaS billing, and a one-to-two-hour weekly operating target are explicitly treated as future targets. They are not presented as current metrics or included capabilities.
